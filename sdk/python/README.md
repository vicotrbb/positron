# Positron Python SDK

Generated by the Rust Public Interface owner from the canonical Protobuf/API definition. Python 3.11 or later is required. The package uses only the standard library at runtime. TypedDict request/result types preserve the public JSON representation; Protobuf JSON 64-bit integers retain decimal strings and native administration integers retain Python's exact integers. Bytes use base64 and cursors remain opaque.

```sh
cargo run --locked -p positron-api --example generate_python_sdk -- sdk/python
python3 -m venv /tmp/positron-python-build
/tmp/positron-python-build/bin/pip install setuptools==80.9.0 build==1.3.0 packaging==25.0 pyproject_hooks==1.2.0
SOURCE_DATE_EPOCH=1700000000 /tmp/positron-python-build/bin/python -m build --no-isolation sdk/python
```

Install the generated wheel into a clean virtual environment with `pip install --no-deps /absolute/path/to/positron_sdk-VERSION-py3-none-any.whl`.

```python
from positron_sdk import PositronClient
client = PositronClient('https://localhost:8443')
capability = client.capability_negotiate({'api_major': 1})
```

TLS certificate verification is mandatory for HTTPS. Plaintext requires the explicit `allow_plaintext=True` constructor option. URL credentials, redirects and invalid bearer headers are refused. Credentials are passed per call and never stored by the client. Every request, response, cursor and deadline is bounded. The total call deadline includes DNS, TCP/TLS, headers and body. At most 16 unfinished connection attempts exist process-wide; a stalled OS resolver keeps its slot until it returns, while callers fail by their deadline and never send a late application request. Cancelled sockets close when resolution returns. Request timers are always cancelled and joined before return. Transport loss is explicitly ambiguous and never retried automatically. Closing a failed HTTP connection does not cancel a server lease: use `log_query_cancel` with the original authenticated query or Tail cursor.

Session and Tail calls negotiate current capabilities before each operation. An additive-compatible v1 Schema Digest may differ. Unsupported capabilities return `QueryError` with `UnsupportedFeature`. The server owns all retry, completion and admission policy.

Keep one `BatchTracker` per query. Feed every response to `filter` and consume only returned new batches. It retains one receipt and fixed digest state, rejects gaps and changed content atomically, and deduplicates verified replays. `terminal_status` distinguishes complete, continued and incomplete. Resume only using the server's cursor. For Tail use `BatchTracker('tail')`, then explicitly include `acknowledgement()` in the next poll after consumption. Abandoning a request never implies server cancellation.
