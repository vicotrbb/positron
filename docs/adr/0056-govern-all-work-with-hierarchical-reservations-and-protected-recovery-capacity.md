# Govern all work with hierarchical reservations and protected recovery capacity

Release 1 places ingestion, queries, tails, compaction, retention, backup, restore, encryption, and administration under one Storage Kernel Resource Governor. Global ceilings honor actual process, cgroup, filesystem, and descriptor capacity; tenant quotas nest beneath them. Work reserves bounded memory, queue capacity, and disk headroom before admission, and already-admitted durability work retains enough capacity to finish. Scheduling prioritizes durability and recovery, security and lifecycle administration, ingestion, interactive reads, then ordinary maintenance and backups, with weighted fairness and progress guarantees preventing tenant or class starvation. A protected Recovery Reserve keeps retention, emergency compaction, purge, repair, fencing, and safe shutdown viable. Healthy, soft-pressure, and hard-pressure Disk Pressure States drive explicit throttling and rejection; hard pressure rejects new ingestion and disk-growing maintenance without disabling safe reads or recovery paths. Every queue is bounded, overload produces typed retryable responses and observable reasons, quota changes are audited, and Kubernetes resource controls supplement rather than replace native admission.

Bootstrap schema reconstruction runs sequentially before serving. It holds a tenant-attributed protected Repair reservation for its complete bounded memory peak, one task slot, one I/O permit, and one CPU work unit throughout reconstruction. This is a peak worker claim, rather than a claim for the sum of all work needed to recover previously accepted history. Each complete replay block, reachable-index collection, and final pruning traversal independently retains its checked canonical cumulative semantic work ceiling and cancellation observer; increasing a decoded delta's checked bound does not reset work already consumed. The retained schema and reachable-index cardinalities remain hard bounded. This distinction prevents accepted history from making restart impossible merely because cumulative reconstruction work exceeds an instantaneous worker allowance. It applies only to sequential bootstrap recovery, which finishes or fails before ordinary serving begins; ordinary serving replay continues to reserve its complete operation work. The recovery claim preserves tenant quota and protected-pool enforcement, so unavailable peak memory or worker capacity still produces an explicit startup refusal. It does not reattribute tenant work to the system, fabricate CPU slices, reset cumulative budgets, or relax serving fairness.
