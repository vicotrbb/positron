## Findings and resolutions

| Severity | Finding and root cause | Resolution and evidence |
| --- | --- | --- |
| P1 | Active-ledger recovery treated a missing durability frontier as an empty segment even when acknowledged payload existed; it could silently truncate acknowledged data. | Publish an authenticated empty frontier before making a new active segment reachable. Refuse payload-bearing segments without the proof, preserve ambiguous bytes, and retain compatibility with legacy header-only segments. A failing acknowledged-append/deleted-frontier regression, interrupted-first-append tests, public reopen regression, and corruption fuzz input cover this boundary. |
| P1 | SIGKILL left the native Unix Control pathname behind, preventing ordinary restart. | Reclaim only a refused, owner-only socket beneath a protected directory. Nonblocking probing, metadata checks, and a directory lock preserve live peers and fail closed on uncertain ownership or competing recovery. Unit tests cover stale, active, unsafe, and competing sockets; the executable test kills and restarts without manually deleting the pathname. |
| P1 | Startup schema reconstruction compared a growing cumulative replay estimate against the tiny native tenant CPU capacity, so valid acknowledged ingestion could make the instance unrestartable. | Retain tenant-attributed protected Repair admission for complete peak memory and one sequential CPU/task/I/O worker. Keep canonical checked decode/reconciliation, reachable-index and pruning work ceilings independently. A failing public 64-ingest/reopen regression covers recovery without a graceful checkpoint. ADR-0056 explicitly records this bootstrap-only peak-versus-total distinction; normal serving admission keeps its full work claim. |
| P2 | Trace-summary binary search used `upper / 2` instead of a midpoint relative to `lower`, and advanced one position after a greater comparison. This missed retries and broke sorted insertion. | Correct midpoint and lower-bound advancement. Public snapshot parity covers retries, conflicts, and insertion; focused tests cover boundaries, work limits, and cancellation. |
| P2 | A completed incremental trace-summary maintainer survived retention while retaining observations removed from the Catalog view. | Compare fixed-size evidence of the previous snapshot’s authenticated block identities/digests. Replay and release obsolete reservations when reachability changes; preserve incremental progress across seals and unrelated Catalog publications. Public retention and reservation regressions plus a stronger exact-count fuzz oracle cover the change. |
| P2 | Active integrity verification reported zero bytes while decoding its committed payload, bypassing the verification byte budget. | Authenticate header/frontier bounds before traversal, enforce the budget, and account for the verified durable prefix and frontier. The failing one-byte-budget regression now reports incomplete rather than verified. |
| P2 | Missing, repeated, or misplaced `serve` arguments could launch a server. | Require exactly one leading command; regression cases include empty invocation and flags preceding the command. |
| P2 | Native HTTP serialization produced incorrect 204/408 reason phrases and emitted Content-Length on 204. | Emit `204 No Content` without body or Content-Length and `408 Request Timeout`. Focused wire regressions and real Loki ingestion cover the behavior. |
| P2 | Native HTTP started the body clock before internal authorization/admission waits, rejecting complete buffered requests when Catalog ownership was busy. | Begin the body phase at first body I/O while retaining the original absolute request deadline and per-byte non-refresh behavior. A deterministic receiver regression reproduces the 400; a companion regression verifies the total deadline still rejects excessive waiting. |
| Dependency security | Locked h2 and rustls versions matched published security advisories. | Update exact pins and both lockfiles to h2 0.4.16 and rustls 0.23.45. The final dependency audit reports zero vulnerability matches. |

The dependency findings correspond to [h2 empty DATA frame resource exhaustion](https://github.com/hyperium/hyper/security/advisories/GHSA-q83h-524g-xf6h) and [rustls TLS 1.3 encryption-level boundary handling](https://github.com/rustls/rustls/security/advisories/GHSA-2mjx-qc3c-rqvc). The latter does not allow arbitrary unauthenticated handshake contents: transcript authentication remains relevant. Informational unmaintained-package warnings remain for adler (through pinned flate2/miniz_oxide) and proc-macro-error2 (through age/i18n-embed-fl); no advisory suppression was introduced. Evaluate these dependency migrations separately with gzip and support-bundle compatibility coverage.

The active-segment format document is synchronized with the corrected durability-proof behavior. ADR-0056 is updated to correct startup recovery accounting: one sequential protected worker plus independent total semantic work limits. The other repairs enforce the existing accepted decisions. Runtime directly uses the already-resolved rustix package for safe Unix descriptor/probe/locking operations instead of adding a new unsafe adapter.

## Performance and follow-up

Bootstrap recovery is sequential rather than CPU time sliced. Existing hard Catalog cardinality limits bound some uninterrupted traversals and therefore cancellation latency. The public replay builder is documented as bootstrap-only; the current production call graph obeys that phase, but the type does not enforce it. Preserve that restriction in future callers.

The corrected sorted lookup needs 12 comparisons for an end insertion among 4,096 span identities, compared with 4,096 before the repair, about 341 times fewer comparisons. This deterministic work measurement establishes the local algorithmic improvement; it is not a claim about end-to-end throughput. The bounded real-binary ingestion measurement used a debug build, durable loopback and 16 serial JSON requests containing 64 records (4,784 encoded bytes): 7.005 seconds, approximately 9.1 records/second. The isolated instrumented run took 12.507 seconds, approximately 5.1 records/second. These include storage synchronization costs and are diagnostic workloads rather than capacity benchmarks.

Remaining investigative performance work: trace staging clones accumulated state per observation and can incur quadratic copying for large traces; tail candidate insertion sorting is bounded but comparison-heavy; resumable query pages currently materialize/hash the result to find a resume key. Existing budgets limit these paths. Optimizing them requires representative workloads and rollback/cancellation regressions, rather than speculative abstraction changes in this pass.

Native query capacity is a material existing limitation: the default principal has a 16-unit CPU ceiling, and log execution scans committed history before applying the temporal filter. The 67-log executable fixture exceeds that ceiling even for narrow time windows, and the runtime convenience method maps the explicit incomplete budget outcome to `CapacityUnavailable`. The final binary test asserts this refusal; it does not claim to return all workload records. Follow-up should coordinate useful query admission defaults with bounded temporal pruning and preserve cumulative budget, cancellation, and terminal semantics. This audit does not enlarge production quotas to make a test pass.

Other follow-up: test blocking public API dispatch under the async timeout with a deliberately slow real endpoint; qualify crash/recovery on Linux/container/Kubernetes and representative filesystems; complete public query, backup/provider/distribution integration and their external acceptance tests according to the roadmap. Planned surfaces are readiness gaps, not defects manufactured by this audit.
